# Qwen3.5 2B vs Qwen3 1.7B 实验记录

测试日期：2026-11-08

## 固定条件

- GPU：NVIDIA GeForce RTX 2050 4GB
- 后端：llama.cpp CUDA，build b12013
- Qwen3.5：`Qwen3.5-2B-Q4_K_M.gguf`
- Qwen3：`qwen3-1.7b-4bit.gguf`
- GPU 全量卸载：`-ngl 99`
- 上下文：`-c 8192`
- 单并发：`-np 1`
- 采样：`temperature=0.1, top_p=0.95, top_k=50, repeat_penalty=1.1`
- 关闭 reasoning：`-rea off --reasoning-budget 0`

## 测试集

复用 `../lfm3_vs_qwen3/benchmark.py`，覆盖：

- 中文/英文精确输出
- 中文/英文数学
- 中文/英文 JSON 提取
- 中文/英文告警分类
- 中文/英文工具选择
- 中文/英文工具链
- 路径长度工具
- 较长上下文检索
- 网络概念问答

每个模型运行 15 个用例 × 3 轮，共 45 次。

## 总体结果

| 指标 | Qwen3.5 2B | Qwen3 1.7B |
|---|---:|---:|
| 任务正确率 | 100.0% | 100.0% |
| 格式严格遵循率 | 93.3% | 86.7% |
| 中位耗时 | 1.323s | 1.130s |
| P95 耗时 | 2.784s | 2.041s |
| 输出 token 中位数 | 32 | 27 |
| 截断次数 | 0 | 0 |

## 关键差异

Qwen3.5 的优势：

- 中文工具链严格输出格式通过 3/3，Qwen3 为 0/3。
- 输出 JSON、分类、数学和长上下文检索都稳定。
- 短回答场景的 decode 速度更高，约 35–41 token/s。

Qwen3 的优势：

- 工具选择中位耗时约 1.17s，Qwen3.5 约 1.98–2.09s。
- 路径长度工具中位耗时约 1.50s，Qwen3.5 约 2.09s。
- 单次工具调用输出约 27 token，Qwen3.5 约 37 token。
- 总体中位和 P95 延迟都更低。

## 实际 Agent 端到端测试

当前 `main_test.py` 使用英文提示词和英文用户输入。

| 轮次 | Qwen3.5 BFS | Qwen3.5 路径 | Qwen3.5 总计 |
|---|---:|---:|---:|
| 1 | 3.271s | 2.405s | 5.884s |
| 2 | 2.681s | 2.032s | 4.755s |
| 3 | 2.636s | 2.089s | 4.762s |

Qwen3.5 中位端到端为 `4.762s`。

相同英文配置下，Qwen3 1.7B 的中位端到端约 `3.280s`。

## 结论

两个模型各有优势：

- 如果只看当前网络运维 Agent 的交互延迟，Qwen3 1.7B 更好。
- 如果更看重输出格式遵循和工具链稳定性，Qwen3.5 2B 更好。
- Qwen3.5 的正确率没有超过 Qwen3，因为 Qwen3 在这套测试中已经达到 100%。
- Qwen3.5 付出了更多工具调用 token、约高 17% 的总体中位延迟、
  约高 36% 的 P95 延迟和约高 45% 的实际 Agent 端到端延迟，
  换来了更高的严格格式遵循率。

当前应用的主要目标是低延迟工具编排，因此默认仍建议使用 Qwen3 1.7B。
如果后续把输出格式正确率作为硬性指标，可以在非实时路径或复杂工具任务中切换到 Qwen3.5 2B。
