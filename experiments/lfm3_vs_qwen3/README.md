# LFM3 1.7B vs Qwen3 1.7B 实验记录

## 目的

在相同硬件、推理后端和采样参数下，比较：

- LFM3-1.7B-Q4_K_M
- Qwen3-1.7B-4bit

重点回答两个问题：

1. LFM3 是否在某些任务上能够超过 Qwen3？
2. LFM3 的端到端延迟是否可以通过提示词或调用方式优化到与 Qwen3 相同水平？

## 固定条件

- GPU：NVIDIA GeForce RTX 2050 4GB
- 后端：llama.cpp CUDA，build b12013
- GPU 全量卸载：`-ngl 99`
- 上下文：`-c 8192`
- 单并发：`-np 1`
- 采样：`temperature=0.1, top_p=0.95, top_k=50, repeat_penalty=1.1`
- 关闭 reasoning：`-rea off --reasoning-budget 0`
- 每个测试用例运行 3 轮

## 测试维度

| 维度 | 用例 |
|---|---|
| 中文精确遵循 | 只输出指定中文或数字 |
| 英文精确遵循 | 只输出指定英文或数字 |
| 中文 JSON | 从告警文本提取固定 JSON |
| 英文 JSON | 从告警文本提取固定 JSON |
| 中文分类 | 仅输出告警类别标签 |
| 英文分类 | 仅输出告警类别标签 |
| 中文工具选择 | 选择 BFS 工具并生成正确参数 |
| 英文工具选择 | 选择 BFS 工具并生成正确参数 |
| 中文工具链 | 调用 BFS、使用工具结果、计算路径长度 |
| 英文工具链 | 调用 BFS、使用工具结果、计算路径长度 |
| 较长上下文 | 从填充文本中检索唯一暗号 |
| 网络概念问答 | 检查丢包和时延两个关键概念 |

## 指标

- 正确率：任务结果是否正确
- 格式遵循率：是否只输出要求的内容
- 总耗时：从请求开始到完整响应结束
- 输出 token：包括工具调用和最终回答
- decode token/s：llama.cpp 报告的预测速度
- 截断率：`finish_reason=length` 的比例

## 运行方式

先启动目标模型服务，确保监听 `127.0.0.1:8000`，然后运行：

```bash
/home/ssshion/miniconda3/envs/network_agent/bin/python \
  experiments/lfm3_vs_qwen3/benchmark.py \
  --label lfm3 \
  --output experiments/lfm3_vs_qwen3/lfm3_results.json
```

Qwen3 使用同一命令，将 `--label` 和输出文件改为 `qwen3`。

采样参数可以通过命令行覆盖，例如：

```bash
/home/ssshion/miniconda3/envs/network_agent/bin/python \
  experiments/lfm3_vs_qwen3/benchmark.py \
  --label model-name \
  --temperature 1.0 \
  --top-p 0.95 \
  --top-k 20 \
  --repeat-penalty 0 \
  --output result.json
```

`--repeat-penalty 0` 表示请求中不设置重复惩罚。

## 结果

测试日期：2026-11-07

每个模型共运行 45 次，即 15 个用例各运行 3 次。

### 总体结果

| 指标 | LFM3 1.7B Q4_K_M | Qwen3 1.7B 4bit |
|---|---:|---:|
| 任务正确率 | 80.0% | 100.0% |
| 格式严格遵循率 | 86.7% | 86.7% |
| 单请求耗时中位数 | 1.301s | 1.130s |
| 单请求耗时 P95 | 8.065s | 2.041s |
| 输出 token 中位数 | 29 | 27 |
| 截断次数 | 2 | 0 |

因此格式严格遵循率相同。正确率按“工具调用正确且最终路径正确”计算。

### 失败样本

LFM3 的数学题虽然包含正确答案，但会附加算式或内部推理文本：

```text
4 + 3 = 7

7
```

英文数学题输出了大段 `<think>` 文本后才给出 `9`。

长上下文题中，LFM3 一开始正确检索到 `BLUE-42`，随后继续分析并重复输出，
三轮中有两轮达到测试输出上限，未能按“只回答暗号”结束。

### 结论

在这套覆盖格式遵循、JSON、分类、工具选择、工具链、数学、长上下文和
网络问答的 45 次测试中：

- LFM3 没有在任何用例上超过 Qwen3。
- 两者在 12/15 个用例上的正确率相同。
- LFM3 在中文数学、英文数学和长上下文检索上明显落后。
- LFM3 在全部 15 个用例的中位耗时上都高于 Qwen3。
- LFM3 的 P95 延迟主要由长上下文重复生成和截断造成。

因此，针对当前网络运维 Agent、同一 llama.cpp 后端和 RTX 2050 4GB 环境，
Qwen3 1.7B 4bit 是更稳妥的选择。

该结论不代表 LFM3 在更大上下文、更复杂 Agent 工作流或领域微调后仍然较差；
这些需要用覆盖 8K 以上上下文和多步工具编排的扩展测试集继续验证。
